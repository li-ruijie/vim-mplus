1. INTRODUCTION                                       *vim-mplus-introduction*

vim-mplus provides syntax highlighting, folding, indentation, completion,
and commands for Mplus statistical software files (.inp input files and
.out output files).

    https://www.statmodel.com/

==============================================================================
2. INSTALLATION                                       *vim-mplus-installation*

Using a plugin manager (e.g., vim-plug): >vim

    Plug 'li-ruijie/vim-mplus'
<
Or copy the plugin contents to your Vim runtime directory.

Run |:helptags| after installing to generate help tags: >vim

    :helptags ALL
<

3. FILETYPES                                             *vim-mplus-filetypes*

The plugin registers two filetypes:

    *mplus-inp*    .inp and .mdg files (Mplus input / diagrammer)
    *mplus-out*    .out files (Mplus output)

Other programs use the .inp and .out extensions as well, so the plugin
looks at the content of these files before it sets a filetype:

    - A new .inp file, or one that holds only blank lines, is mplus-inp.
    - Any other .inp file is mplus-inp when its first line of code is an
      Mplus command header, that is one of TITLE, DATA, VARIABLE, DEFINE,
      ANALYSIS, MODEL, OUTPUT, SAVEDATA, PLOT, and MONTECARLO followed by
      a colon. The header may be in any case, may be shortened to four or
      more letters ("anal:"), and may carry a second word after DATA or
      MODEL ("MODEL INDIRECT:"). Blank lines, comment lines, and block
      comments above it are passed over, and it must lie within the first
      500 lines.
    - A .out file is mplus-out when one of its first ten lines starts with
      "Mplus VERSION" or is "MUTHEN & MUTHEN", as Mplus output does. A new
      .out file gets no filetype.

A filetype that another plugin has already set is kept. For a file that the
plugin does not recognise, set the filetype by hand: >vim

    :setfiletype mplus-inp
<
A .mdg file is always mplus-inp.

4. SYNTAX HIGHLIGHTING                                     *vim-mplus-syntax*

Syntax rules are split across three files:

    syntax/mplus.vim       Shared base (keywords, operators, numbers, comments)
    syntax/mplus-inp.vim   Input: sources mplus.vim, section headers, fold regions
    syntax/mplus-out.vim   Output: standalone (does not source mplus.vim),
                           all-caps headers, fold regions

Output files do not source the shared base because Mplus keywords appear
as plain English in output text and should not be highlighted.

Highlight groups:~

    *mplusStatement*   Links to |hl-Statement|
                     Section names, output options, TECH keywords.

    *mplusCommand*     Links to |hl-Statement|
                     Command options and parameters (ESTIMATOR, STARTS, etc.).

    *mplusModel*       Links to |hl-Function|
                     Model operators: BY, ON, WITH, |, &, *, @, #, [], (),
                     SQRT, EXP, LOG, DO, END.
                     ON after = (e.g., BASEHAZARD = ON) links to mplusCommand.
                     Bayesian priors: N, IG, IW, D (used with ~).
                     Logical/comparison: EQ, NE, GT, LT, GE, LE, AND, OR, NOT.

    *mplusNumber*      Links to |hl-Number|
                     Integers, floats, and scientific notation (1.5E-3, 0.100D-05).
                     A digit inside a name (y1, x2a, ex3.1.dat) is not a
                     number. A minus that starts a value is part of the
                     number (@-1, *-.5), and a minus after a name or a
                     number is an operator (y1-y4).

    *mplusSection*     Links to |hl-Include|
                     Section headers (TITLE:, MODEL CONSTRAINT:, etc.)
                     and class/level labels (%OVERALL%, %c#1%, etc.).

    *mplusComment*     Links to |hl-Comment|
                     Line comments starting with !
                     Block comments delimited by !* and *! (spell-checked).

    *mplusSpeccom*     Links to |hl-Special|
                     Connectors: ARE, IS, =.

    *mplusHeader*      Links to |hl-Type|
                     Timestamp and section headers in output files.

    *mplusTitle*       Links to |hl-String|
                     TITLE section body (suppresses keyword highlighting).

    *mplusString*      Links to |hl-String|
                     Quoted strings ("..." and '...').

5. FOLDING                                               *vim-mplus-folding*

Both filetypes use 'foldmethod'=syntax (set in ftplugin files).

Input files ~
Each section (TITLE:, DATA:, VARIABLE:, MODEL:, etc.) is a separate fold.
Headers with a second word, such as MODEL CONSTRAINT: and DATA IMPUTATION:,
are fold boundaries as well.

Where a section starts ~
                                                         *vim-mplus-sections*
Folding, indentation, the formatter, and the highlighting of the input
echoed in an output file share one rule, which follows what Mplus 9.1.1
does with an input. A section starts on a line whose first word is a
command name, followed by a colon either at once or after one more word.
The names are TITLE, DATA, VARIABLE, DEFINE, ANALYSIS, MODEL, OUTPUT,
SAVEDATA, PLOT, and MONTECARLO, in any case, in full or shortened to four
or more letters. The line may be indented, and spaces may stand before the
colon.

The rule is the same inside a TITLE. A semicolon does not end a title, and
these lines are title text:

    Step 2: the model with covariates
    the model: two groups
    model with covariates: two groups
    models: two groups

These lines end a title, since Mplus reads each as a command:

    Model comparison: two groups
    data: one file
    Variable names: a list

What Mplus does with a section depends on its header:

    anal:               The command, here ANALYSIS.
    MODEL word:         With MODEL in full, a MODEL subcommand (INDIRECT,
                        CONSTRAINT, TEST, PRIORS, and so on, with the name
                        in full), or else the model of the group or class
                        with that label.
    DATA IMPUTATION:    A DATA subcommand, with its name in full
                        (IMPUTATION, MISSING, TWOPART, WIDETOLONG,
                        LONGTOWIDE, SURVIVAL, COHORT).
    DATA notes:         An error, "Unknown command".
    data impu:          Nothing. With a shortened subcommand name Mplus
                        passes over the lines up to the next header and
                        gives no message.
    mode indirect:      Nothing, in the same way. This holds for a
    variable names:     shortened MODEL with a second word, and for a
                        second word after any command but DATA and MODEL.

The formatter leaves a header of the last three kinds as written, with the
lines below it, since the full name ("MODEL INDIRECT:") would make Mplus
read a section that it passed over before.

test/mplus-rules.sh checks the rule against an installed Mplus, with the
cases of test/header-cases.txt.

Output files ~
Folds span between all-caps headers (e.g., MODEL FIT INFORMATION,
STANDARDIZED MODEL RESULTS) and specific mixed-case headers from
model fit output (Loglikelihood, Information Criteria, Chi-Square
Test of Model Fit, RMSEA, SRMR, WRMR).

6. INDENTATION                                         *vim-mplus-indentation*

For mplus-inp files, 'indentexpr' applies contextual rules:

    - Section headers (full or abbreviated) are placed at column 0. See
      |vim-mplus-sections| for what counts as a header.
    - Lines after a section header are indented by one 'shiftwidth'.
    - DO(...) loops increase indent by one level; END DO decreases it.
    - Other lines preserve the previous line's indentation.

7. COMPLETION                                           *vim-mplus-completion*

Omni-completion is enabled for mplus-inp files via |syntaxcomplete|.
Press CTRL-X CTRL-O in insert mode to complete any Mplus keyword defined
in the syntax file.

8. FORMATTING                                           *vim-mplus-formatting*

For mplus-inp files, 'formatexpr' is set to a custom formatter invoked
with |gq|. The formatter performs the following operations on the
selected range:

    - Replaces tabs with 4 spaces and strips trailing whitespace.
    - Preserves TITLE body lines (free-form text, whitespace cleanup only).
      A title line may hold a colon. It ends the title when it begins with
      a command name that is followed by a colon at once or after one more
      word, as it does for Mplus. See |vim-mplus-sections|.
    - Preserves comment lines and block comments (whitespace cleanup only).
    - Splits section headers onto their own line (e.g.,
      "DATA: FILE IS ..." becomes "DATA:" followed by "  FILE IS ...") and
      writes an abbreviated header in full ("ANAL:" becomes "ANALYSIS:").
    - Preserves a header that Mplus does not read, such as
      "mode indirect:", and the lines of its section (whitespace cleanup
      only). See |vim-mplus-sections|.
    - Uppercases all code (Mplus is case-insensitive; standard convention).
      Quoted strings and file names keep their spelling, since a file name
      is case-sensitive outside Windows.
    - Replaces the IS/ARE connector after an option name with =.
    - Expands a keyword abbreviation to its full form where Mplus reads a
      keyword: the option name that starts a statement in the DATA,
      VARIABLE, ANALYSIS, SAVEDATA, PLOT, and MONTECARLO sections, and
      every word of the OUTPUT list. Variable names are never expanded, so
      "CLUSTER = clus;" stays as it is, and MODEL and DEFINE sections are
      only uppercased.
    - Reads an abbreviation as an option of the section it stands in, since
      the same letters can name different options. "ESTI" becomes ESTIMATOR
      in ANALYSIS and ESTIMATES in SAVEDATA, "STAR" becomes STARTS in
      ANALYSIS and STARTING in MONTECARLO, and "SAMP" becomes SAMPSTAT in
      OUTPUT and SAMPLE in SAVEDATA. An abbreviation that belongs to no
      option of its section is left as written.
    - Expands an abbreviation as Mplus 9.1.1 reads it. Four letters are
      enough, also where two options of a section start with the same
      four. "INTE" is INTEGRATION, and INTERACTIVE needs "INTER". "PARA"
      is PARAMETERIZATION, and PARALLEL needs "PARAL".
    - Expands an OUTPUT option from its one short form ("SAMP", "RES",
      "MOD", "CINT", and "BOOT" and "CLUS" in parentheses). Mplus rejects
      any other shortening of an OUTPUT option, such as "RESI" or "MODI",
      and the formatter leaves it as written.
    - Re-indents using 'indentexpr'.

The section and statement that a range belongs to are read from the lines
above it, so formatting part of a file gives the same result as formatting
all of it.

The formatter also sets buffer-wide: 'fileformat'=unix,
'fileencoding'=utf-8, 'nobomb', 'endofline'.

Buffer settings applied by ftplugin:~

    'comments'      :!
    'commentstring' !%s
    'textwidth'     90
    'formatoptions' -t +croql
    'tabstop'       4
    'softtabstop'   4
    'shiftwidth'    4
    'expandtab'     on
    'fileencoding'  utf-8
    'bomb'          off

9. COMMANDS                                             *vim-mplus-commands*

These commands are available in mplus-inp buffers:

                                                                       *:Mout*
:Mout           Open the corresponding .out file in a vertical split.
                For example, if editing model.inp, opens model.out.

                                                                       *:Mrun*
:Mrun           Run Mplus on the current file. On Windows, launches via
                `start ""`. On Linux, runs in the background.
                The executable can be configured with |g:mplus_executable|.

10. CONFIGURATION                                  *vim-mplus-configuration*

                                                         *g:mplus_executable*
g:mplus_executable ~
    Type: |String|
    Default: "mplus"

    Path to the Mplus executable used by |:Mrun|. Set this in your |vimrc|
    if Mplus is not on your PATH: >vim

        let g:mplus_executable = 'C:\Program Files\Mplus\mplus.exe'
<
    Or on Linux: >vim

        let g:mplus_executable = '/opt/mplus/mplus'
<

11. SNIPPETS                                             *vim-mplus-snippets*

UltiSnips snippets are provided for common Mplus analyses. Requires the
UltiSnips plugin (https://github.com/SirVer/ultisnips). Type the trigger
in insert mode and press <Tab> to expand.

    Trigger   Description ~
    inp       Full input file skeleton (TITLE/DATA/VARIABLE/MODEL/OUTPUT)
    sec       Generic section header
    cfa       Confirmatory factor analysis
    sem       Structural equation model (CFA + structural paths)
    lgm       Latent growth model
    lca       Latent class analysis
    gmm       Growth mixture model
    mlm       Multilevel (TWOLEVEL) model
    efa       Exploratory factor analysis
    mc        Monte Carlo simulation
    mi        Multiple imputation (DATA IMPUTATION)

All snippets use tab stops for user input. See |UltiSnips| for usage.
